## 1. 项目定位

目标不是设计一个新的前端框架，而是设计一种面向大语言模型生成的声明式交互视觉语言（LLM-native
Interactive Visual Language）。

核心目标：

-   极小语言表面，适合嵌入 System Prompt；
-   高表达能力，可生成科研成果展示、工程数字孪生、交互论文、数据应用、模拟系统甚至游戏级交互；
-   通过确定性编译器和运行时，将简单 DSL 转换为复杂 Artifact / Widget /
    Scene。

核心理念：

> 模型负责表达意图，编译器负责实现复杂性。

------------------------------------------------------------------------

# 2. 为什么现有方案不足

## 2.1 HTML / React

优势：

-   表达能力强；
-   生态成熟。

问题：

-   Token 消耗巨大；
-   LLM 生成稳定性差；
-   需要处理大量工程细节。

模型不应该关注：

-   CSS 布局；
-   DOM 生命周期；
-   事件绑定；
-   响应式适配。

------------------------------------------------------------------------

## 2.2 Visualization DSL

例如 Vega-Lite 等。

优势：

-   声明式；
-   图表生成方便。

不足：

主要解决：

> 数据如何映射到视觉。

无法自然描述：

-   世界状态；
-   长时间演化；
-   复杂交互；
-   多对象行为依赖。

------------------------------------------------------------------------

# 3. 核心设计原则

## 3.1 小语言，大运行时

语言本身只描述：

-   世界是什么；
-   对象有什么状态；
-   对象之间有什么关系；
-   状态如何变化。

复杂实现由：

-   Compiler
-   Intermediate Representation
-   Runtime
-   Widget Registry

完成。

# 5. Universal Visual IR

核心不是 Widget，而是统一世界模型。

## 5.1 Scene

描述空间结构：

    scene
     ├ layer
     │   ├ node
     │   └ node
     └ layer

支持：

-   2D
-   3D
-   图层叠加
-   相机
-   坐标变换

------------------------------------------------------------------------

## 5.2 Entity

对象抽象：

    entity cell:

        position
        state
        appearance
        behavior

例如：

-   细胞
-   分子
-   建筑
-   节点
-   工程设备

均可统一表示。

------------------------------------------------------------------------

# 6. 完备性交互模型

仅有视觉原语不足以支持游戏级交互。

必须加入：

## 6.1 State

世界状态：

    state selected = none
    state year = 2026

------------------------------------------------------------------------

## 6.2 Event

外部输入：

    click
    hover
    drag
    change
    collision

------------------------------------------------------------------------

## 6.3 Rule

状态变化：

    when A.selected:

        B.visible = true

------------------------------------------------------------------------

## 6.4 Reactive Binding

对象关系：

    B.position <- A.position

避免大量 imperative code。

------------------------------------------------------------------------

## 6.5 State Machine

复杂过程：

    idle
     |
    start
     |
    running
     |
    finished

适用于：

-   工程流程；
-   科研流程；
-   游戏逻辑。

------------------------------------------------------------------------

# 7. 时间模型

需要同时支持两类时间。

## 7.1 Presentation Time

动画：

    animate opacity:

    0 -> 1
    duration 2s

------------------------------------------------------------------------

## 7.2 Simulation Time

动态系统：

    tick 60:

    update state

用于：

-   数字孪生；
-   生物模拟；
-   物理系统。

------------------------------------------------------------------------

# 8. Widget 的定位

Widget 不是语言核心。

Widget 是高层宏。

例如：

    show timeline

内部展开：

    scene

    +
    paths

    +
    text

    +
    interaction

    +
    animation

类似：

高级语言编译到机器码。

------------------------------------------------------------------------

# 9. 推荐核心语法类别

不是大量组件，而是少量计算原语：

    artifact

    layer

    node

    resource

    rule

    event

    animate

    bind

# 11. 最大挑战

## 11.1 表达能力与简洁性的平衡

不能：

-   退化成 HTML；
-   退化成 Python。

目标：

> 图灵完备不是第一目标，视觉完备 + 交互完备 + 可验证编译更重要。

------------------------------------------------------------------------

## 11.2 LLM 友好性

设计原则：

-   默认值强；
-   语义优先；
-   少参数；
-   强类型；
-   可验证；
-   错误可自动修复。

------------------------------------------------------------------------

# 12. 最终愿景

建立一种：

> 面向 AI 时代的通用成果表达语言。

输入：

    科研想法
    工程方案
    数据关系
    模拟规则

输出：

    交互式报告
    数字孪生
    科研图谱
    动态模型
    游戏级可视化

核心不是生成网页。

而是让大模型能够生成一个"可计算、可交互、可演化的小世界"。
